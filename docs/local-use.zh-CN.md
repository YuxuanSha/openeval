# 本机使用

在项目文件夹双击 **Start OpenEval.command**，浏览器将打开 **http://127.0.0.1:4318**。关闭启动终端不会结束服务。重复启动会复用同一实例。

第一次使用时点击左下角“本地模式”，确认 Codex 已连接。如果尚未登录，在本机终端执行 `codex login` 完成 ChatGPT 登录，再点“重新检查”。不需要填写 API Key。

1. 点击“新任务”。空会话立即保存在近期任务，尚不会执行。
2. 从左栏导入标准、评测集、已有产物、评分或模板；结构化台账使用 JSON、JSONL、CSV 或 TSV。
3. 在输入框使用 `@` 选定版本。只想共建标准时不需要样本；评测已有产物时选择“敏捷评测”；只解释原分时选择“分析已有结果”；按模板出报告时选择“撰写报告”。当前任务类型仍需要明确选择，自由对话不会自动获得新增评分批次的权限。
4. 输入要求并发送。展开 Codex CLI 面板可查看实际命令、文件、审批和阶段事件。产物登记成功后会进入对应资料库；失败会保留文件和错误信息。
5. 有多步明确目标时可在 CLI 执行选项选择目标模式并设置预算、时限与轮次。目标完成和人工验收是两种状态。停止执行会先暂停目标，再中断当前轮次。

双击 **Stop OpenEval.command** 停止主服务。它仅停止身份匹配的实例，不会按端口误杀其他进程。

终端使用方式（后端需要 Node.js 24+）：

```sh
npm start
npm run status
npm stop
```

如果系统默认 Node 较旧，Mac 的 `.command` 启动器优先使用已安装 ChatGPT 自带的 Node，也可通过 `OPENEVAL_NODE` 指定已有的 Node.js 24+。前端构建单独需要 Node.js 22.12+。

常见情况：

- 端口被其他程序占用：启动器会明确拒绝启动第二个实例。可设置 `OPENEVAL_PORT`，启动与停止使用相同端口。
- 引用冲突：重新打开资料版本，确认想使用哪一版；旧版本不会被自动替换。
- 归档失败：原文件仍在任务产物中。修正清单或缺失依据后，在同一会话继续，不要假定已成功入库。
- 提示只读依据被改动：本轮产物保留但不登记，避免把新内容冒充旧快照。检查并恢复任务依据后续聊。
- 等待补充资料：补齐引用再发送；页面重开不会自动执行。

数据默认保存在项目的 `.openeval-product/`。完整备份前先停止服务；不要把此目录、日志、个人报告或凭据提交到源码仓库。项目范围是应用的数据关联边界，不是多用户访问控制或操作系统级读隔离。模型处理使用 OpenAI 云服务，本地存储不代表离线推理。
