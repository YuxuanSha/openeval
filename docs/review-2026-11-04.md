# November 4 reliability review

This is a local development review, not a production launch or business-quality benchmark. The starting checkout was clean at `3e465028874c9140e29dee76607f48104afdd365`. The previous main process had shut down cleanly; it was not treated as a crash.

## Fixed findings

P1 means evidence integrity, unsafe filesystem behavior, or a core workflow failure. P2 means a narrower correctness or usability defect.

| Severity | Reproduction / previous behavior | Change and evidence |
| --- | --- | --- |
| P1 | Replace a task context file or reference directory with a symlink before continuation; preparation followed it. | Refuse symlinks, hard-linked files and non-regular paths; write context through a fresh file. Outside synthetic files remain unchanged. `tests/review.test.ts`. |
| P1 | Modify mounted extracted evidence during a run, then register a report under the original pinned version. | Hash mounted originals, extracted text, selected skills and task contracts. Changed/missing input blocks registration while retaining output bytes. Tampering regression and a normal real CLI report turn passed. |
| P1 | A report manifest could register a replacement standard despite a report-only contract. | Allowed artifact kinds now follow task intent. Report/analysis cannot register standards, datasets or new scores. |
| P1 | Invalid structured content named `.txt` or `.md` silently became a zero-record batch. | All dataset/output/score batches must parse into explicit records, independent of filename. Failed imports create no resource. |
| P2 | A manually uploaded revision inherited the earlier generated task/run/template claims. | Remove execution-derived provenance from manual revisions and record the actual previous snapshot ID. |
| P1 | Nested reasoning items in a completed-turn payload were not removed by the event filter. | Remove reasoning objects recursively; redact persisted assistant and approval displays as well as streamed events. |
| P1 | Opening a Store for inspection marked active runs interrupted; direct server starts could share one directory. | Recovery occurs only at server startup under an exclusive data-directory lease. Readback does not change live status. Genuine clarification waits survive restart; abandoned approval waits expire. |
| P2 | A UTF-8 character split across subprocess chunks could corrupt Chinese evidence text. | Use a streaming UTF-8 decoder; a split-byte protocol fixture preserves the original text. |
| P2 | Opening an API-created project task displayed valid references as unavailable and loaded default-project resources. | Preserve task project IDs; scope resource/memory reads, imports and new tasks to the active task project. Browser readback verifies the real references and report. |

## Remaining boundaries

- Subjective judgment, calibration against human labels, realistic image/video quality, inter-rater agreement, repeat-run variability and large-batch load remain untested in this review.
- The application pins sources and checks input integrity; it does not yet validate arbitrary rubric semantics, per-dimension evidence sufficiency or every report claim automatically. `validationStatus` remains `not_checked` unless separately accepted; a completed run is not an accepted evaluation.
- Choose the appropriate task type before scoring/reporting. Free conversation does not silently gain permission to create new scoring batches. Automatic intent routing remains a product gap.
- Project scoping is an application association rule. This is a local single-user service, not a multi-user access-control system or an OS-level read-isolation boundary. A complete project-switching interface remains outside this revision.
- Feishu delivery was not tested or written; it still requires a verified personal destination. No GitHub push, repository creation or deployment occurred.
- No dependency was added for this review. Existing MIT/third-party notices remain; a final redistribution audit is separate from these functional checks.
