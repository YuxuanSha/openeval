# 已有机评结果分析

输入为机评分数/标签、批跑任务/产物/日志、原标准与指标口径、分析问题及参考模板。输出是来源索引、规范化分析副本、指标字典、计算/连接核查、证据支撑的诊断与报告材料。原评分是待解释证据，不自动正确，也不自动可被替换。

先识别单批、同系统版本、跨系统或多方；只做用户要求的范围。没有比较对象不构造“新旧”；用户要口头解释先直接回答，不强制新建报告。

解析机评HTML内嵌结构化数据优先于页面取整值，留解析过程。将run/session/turn对齐到稳定任务键；logid等经唯一性验证后可连接，行号仅定位，重复item_id不能直接join。任务身份结合原Prompt、有序输入、上下文与数据集；一对多/重复冲突保留，不取第一条。当前输入、输出、trace角色分清。

为每项指标保留原名、原值、尺度、单位、公式、分母集合、过滤条件、缺失策略和源字段。原始分、用户已过滤分、作者补充分析分别命名。用户确认原报告已采用特定筛选口径时，不再替换为另一套规则；发现疑点先报告，若用户要求重算另建analysis_id，不覆盖原评分；真正重评需独立任务范围。

汇总公式缺失时，先给原分分布与有效分母；需要时将均值和满分占比列为作者补充统计，不冒充原指标，也不因此中断可完成的分析。明确没有跨维度综合分，不一定等于缺少单指标汇总规则，两者分别核对。

先看任务完成，再看过程、产物、标签和工程代价。明确未交付、交付不合要求、评测无法观察、不适用各自计数；执行成功/接口成功不等于交付合格。视频读取失败不能写成动作差；单图不能证明全片。归因标签保留原文；分析归并另留映射，标签重叠不相加算总失败。没有直接证据的内部原因标为待核。

多方比较同时呈现各自全量和共同可评集合；共同集合不消除规则差异。不同系统用vs，同系统版本才叙述改善。比例差为百分点，分数差为分，量纲/方向明确。低耗时、低失败率方向相反；不同分母或任务构成不能只凭均值归因能力。

工程数据区分用户墙钟、累计模型/工具时间、缓存与非缓存、失败/重试和唯一请求；无日志写N/A而非0。目标测算固定样本构成、指标定义和目标，标为情景，不把标签重叠当可恢复收益。

先整体问题分布后选高损失、常见、矛盾或边界case；核真实输入/输出/trace。已有分数分析可以在没有任何新judgment时完成。按用户模板交付，给报告撰写流程提供指标与证据。参考[分析契约](assets/analysis-record.json)与[来源决策](references/decisions.md)。
