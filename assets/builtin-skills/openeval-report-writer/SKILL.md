# 评测报告撰写

输入为本次问题、可追溯结果/分析、范围口径、典型证据、用户模板/参考/已有报告及修改范围。输出为模板契约、可消费正文、证据附录、报告版本与交付验证。评分不是此步骤的必需新动作；没有证据不编结果补满模板。

## 先读模板和当前版本
用户指定模板或已有报告时先读取实际内容与revision，识别章节顺序、总览层级、图表样式、案例布局、配色、保护区和修改目标。当前用户要求优先，其次模板与人工修改；旧技能默认仅兜底。单批时参考中“新旧比较”应按当前问题适配，不能伪造比较。只修链接就不改正文。

模板不可读时完成不依赖布局的分析，说明当前未取得模板；不要声称已套用或静默换通用稿。模板里的业务结论不是本批事实。将可变数据与保护内容分开记录，[模板契约](assets/template-contract.json)用于报告绑定。

## 用结论带证据
开头先用少量清晰判断回答问题；后续按用户结构展开必要分布和案例。每个结论回指指标、分母与证据。没有原始观测就只报告来源记载；历史自报、当前核实、建议与演示明确区分。

保留标准原维度/尺度与用户过滤口径，不补总分，不为可比性改分。跨系统用vs，同系统版本可用改善/退步；差值写明主体、参照和单位。图表每格带有效n，颜色辅以文字/符号；未知不涂成0。

案例按能解释结论的价值选，保留任务、预期、输入、实际输出、条款、观察和入选原因。图片在对应单元格，输出缺失明确写状态；视频需要相应时段证据。原始标签与分析原因分开，不强制为每例追加“验收与改进”。来源行号/长台账放附录。

## 修订与验收
报告版本绑定标准/结果或analysis/模板snapshot与内容哈希。修订只处理指定范围，保留用户手动删除或改写内容。写回前核对源revision，遇并发变化先重读合并差异；先检查不确定写入是否已发生，避免重复插入。外发/发布仅在本任务明确授权范围内进行。

完成前从结论反查统计、case、逐项证据和标准；核对覆盖、未判项、配图对应、表格横向可读、链接/附件。用户要HTML需交付实际HTML，不能以另一格式替代；远端写入需回读且区分内容核验与浏览器布局核验。仅本地草稿不能声称远端已发布。

无用户格式时参考[兜底骨架](assets/report-fallback.md)。历史来源与报告修订边界见[方法边界](references/decisions.md)。
